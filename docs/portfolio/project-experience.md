# AI 产品经理项目经历素材

## 简历一行版

独立设计并开发面向连锁门店设备售后场景的 AI Copilot MVP，完成设备状态、告警与故障码建模，搭建基于 SQLite FTS5 的知识库检索和可解释诊断工作流，实现风险分级、证据引用、人工复核和工单草稿闭环。

## 简历三条版

- **业务与产品设计**：针对售后工程师处理设备告警时需要跨系统查状态、查手册、写工单的问题，设计“设备总览—AI 诊断—证据引用—工单草稿”的端到端工作流，明确 AI 建议、事实依据和人工确认边界。
- **AI 能力落地**：设计确定性 Agent 编排，串联设备状态、告警、故障码、相似工单和知识库检索；输出已确认事实、推断、建议、来源和资料不足，支持无 API Key 的本地回退演示及 OpenAI-compatible 模型接入。
- **可靠性与验证**：建立高风险人工复核、禁止自动控制设备和禁止自动提交工单等安全机制，构建 30 条覆盖标准故障、未知问题、无证据和高风险场景的评测集，并提供 FastAPI 接口、可视化工作台和自动化测试。

## 面试讲解顺序

1. **为什么做**：售后工程师处理一个温度异常，通常要先看设备状态，再查告警和故障码，然后翻手册，最后手写工单；信息分散且容易漏掉高风险信号。
2. **用户是谁**：主用户是售后工程师，次用户是门店店长，管理用户是售后主管；MVP 先服务最频繁、最容易量化的诊断和工单准备环节。
3. **AI 做什么**：AI 负责召回资料、整理事实、生成诊断建议和工单草稿，不直接控制设备、不替代工程师判断，也不自动提交工单。
4. **如何防止胡编**：每条诊断拆成事实、推断、建议、来源和资料不足；知识库没有足够证据时明确提示，引用来源只来自演示知识库。
5. **如何评估**：评测引用命中、人工复核判断、缺失证据识别和工单字段完整性；错误案例保留在 `evals/cases.json`，用于后续 Badcase 复盘。

## 面向不同岗位的表述

### AI 应用产品经理

重点强调用户工作流、AI 输出结构、引用可解释性和人机协同闭环。

### AI Agent / 工作流产品经理

重点强调工具调用顺序、状态管理、风险规则、异常分支和人工接管点。

### AI 产品落地 / 解决方案经理

重点强调模拟数据边界、接口设计、部署方式、模型可替换和企业落地时的数据接入清单。

### AIoT 软件产品经理

重点强调设备状态、告警、故障码、售后工单和现场服务之间的数据链路；面试时明确本项目不涉及硬件控制和真实 IoT 接入。
